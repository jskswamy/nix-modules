# Tool reference

What each tool module configures, what it installs, and what it brings with
it. Generated by evaluating the modules — see [Regenerating](#regenerating).

## Does it install the tool?

Most modules install the tool as well as configuring it. A few only write
config and expect the binary from somewhere else, either because the tool
is not distributed through nixpkgs or because it runs another way.

Every tool takes `tools.<name>.package`: set it to another package to swap
what gets installed, or to `null` to keep the config and install nothing.

**Installs the package** (23): `alacritty`, `beads`, `ccstatusline`, `context7-mcp`, `delta`, `difftastic`, `direnv`, `fabric`, `fish`, `git`, `gpg`, `herdr`, `hunk`, `lazygit`, `nvim`, `pet`, `ssh`, `starship`, `tig`, `tmux`, `tmuxp`, `vim`, `zsh`.

**Config only by default** (6): `agentgateway`, `ghostty`, `herdr-app`, `local-mcp`, `mcp-nixos`, `serena-mcp`.

Two of those are platform-dependent, and this page was generated on
`x86_64-linux`:

- `agentgateway` — upstream publishes an aarch64-darwin binary only, so it
  installs there and is config-only everywhere else.
- `ghostty` — deliberately config-only. Upstream's own flake builds the
  terminal on Linux only, and the usual macOS source is the `ghostty@tip`
  Homebrew cask. Set `package` to `pkgs.ghostty` (Linux) or
  `pkgs.ghostty-bin` (aarch64-darwin) to install it with Nix instead;
  ghostty-bin tracks stable releases, so it is a downgrade from the nightly
  cask.

## Summary

### Skillshare activation updates

`tools.skillshare.updateOnActivation` defaults to `false`. Set it to `true`
to update all managed plugin bundles and standalone skills before activation
syncs resources. Updates retain normal audit and local-edit protections;
failures warn and activation continues. Dry runs never update.

The option is independent of `tools.skillshare.syncOnActivation`: disabling
sync does not disable opted-in updates, and plugin updates may modify native
client installations themselves. Updates require network access, can take
several minutes, and include managed resources not declared by this module.
Source refs remain unchanged, so pinned sources stay pinned. Before editing
shared plugin configuration with Skillshare 0.28.2, upgrade all machines that
write it and follow the upstream plugin-state migration guidance.

## Each tool

<a id="toolsk-agentgateway"></a>

### `tools.agentgateway`

Routes Claude Code to the HTTP-native MCP servers, and registers itself as a Claude Code connector. Server definitions live in `config.yaml`, symlinked for instant edits.

- **Installs the package:** no by default — see above
- **Option:** `tools.agentgateway.port`
- **Writes:** `~/.config/agentgateway/config.yaml`

Home Manager activation creates a session key before starting the launch agent.
The launch wrapper only reads and supplies `SESSION_KEY` from
`${XDG_STATE_HOME:-~/.local/state}/agentgateway/session.key`. The key is
generated once per machine, with a private directory (0700) and file (0600),
then reused across restarts and rebuilds. It is never stored in the tracked
YAML or Nix store. Invalid or unreadable state stops startup rather than
silently rotating the key or starting without session encryption.

Moving from the previous inline key generates a fresh key on the first
activation with this module, invalidating existing sessions once. Things Cloud
authentication still comes from the existing agenix environment file.

<a id="toolsk-herdr-app"></a>

### `tools.herdr-app`

Desktop multiplexer client config: font (from the shared `terminal.*` options, written as a generated `settings.json`) and keyboard mappings for the Herdr desktop app. Deliberately config-only — upstream ships no Homebrew cask and no Nix package; the usual source is herdr's install script (`Herdr.app` in /Applications, `herdr-app` symlinked into `~/.local/bin`). Managed via the `terminal` group.

**Key scheme is generated, not stored.** The herdr TUI's `~/.config/herdr/config.toml` `[keys]` is the single source of truth. At activation, `herdr --default-config` supplies the installed binary's baked-in defaults, config.toml applies user overrides, and a generator translates the effective `ctrl+a` prefix scheme into herdr-app's `keys.json` (which takes herdr's two-keystroke sequences — same mechanism as Zed's chains). Bindings with no desktop equivalent (resize_mode, `[keys.command]` plugin blocks, `focus_agent`'s indexed jump) skip loudly on stderr. `~/.config/herdr-app/keys.json` is therefore not a managing symlink: it is regenerated whole on every switch, and the app hot-reloads it. Desktop-only overrides that the TUI cannot express (e.g. alt-backspace as esc+word-delete) go in `tools.herdr-app.extraKeys`.

The app does **not** read `~/.config/herdr/config.toml` itself (checked the source; no migration code) — this generator is the copy-over. Note the prefix steals `ctrl+a` from shells (readline home), exactly as the TUI does inside Ghostty.

The app covers its own bookkeeping: `~/.config/herdr-app/{AGENTS.md,view.json,shared.json,...}` are written by the app on every start, and defaults are installed only when a file is missing, so managed files are read but never overwritten.

The app's terminal panes embed libghostty (upstream vendors the ghostty repo), so terminal rendering is Ghostty's own; but herdr-app exposes no ghostty tuning knobs (font-thicken, cell adjustments, codepoint maps) — only `font`, `font_size`, `font_ligatures` and `option_as_alt`. Refresh `defaults-keys.macos.json` from upstream's `defaults/keys.macos.json` at each herdr-app upgrade; it only carries the chrome keys. The CLI itself (`herdr`) is packaged by `tools.herdr` from upstream release binaries.

- **Installs the package:** no by default
- **Option:** `tools.herdr-app.extraKeys` (desktop-only key sections, merged last)
- **Writes:** `~/.config/herdr-app/settings.json` + regenerated `~/.config/herdr-app/keys.json` (activation)

<a id="toolsk-fresh"></a>

### `tools.fresh`

Fresh terminal editor with Vi mode enabled at startup. Uses the terminal's
ANSI palette, inheriting its theme and light/dark changes (including
Gruvbox in Ghostty), rather than Fresh's fixed dark Gruvbox theme.
It does not change `EDITOR`, `VISUAL`, or the `vi`/`vim` aliases.

- **Installs the package:** yes, plus language servers for Go, Python
  (Pyright), Rust, TypeScript/JavaScript, YAML, TOML, Markdown, Nix,
  JSON/JSONC, HTML/CSS and Bash. Servers start automatically for these languages.
- **Options:** `tools.fresh.package` (nullable), `tools.fresh.languageServers`,
  `tools.fresh.settings` (merged JSON settings).
- **Writes:** `~/.config/fresh/config.json` (read-only; change settings through
  Nix or a project's `.fresh/config.json`, not Fresh's user settings UI).
- **Requires:** the project's toolchain/environment for full analysis, such
  as Go, Cargo/Rust sources or the project's Python environment. Remote
  workspaces need language servers installed on the remote host too.

<a id="toolsk-nvim"></a>

### `tools.nvim`

Neovim (LazyVim). The whole config directory is symlinked, so edits need no rebuild.

- **Installs the package:** yes, plus `tools.nvim.runtimePackages`: the platform
  C compiler, Tree-sitter CLI, Git/download/archive tools, Node/npm, Python with
  pip, Go, ripgrep/fd, nil/alejandra/statix/deadnix/Pkl/Terraform, and the Java
  runtime needed by Mason's Pkl language server.
- **Writes:** `~/.config/nvim`, plus the LaTeX parser, revision marker and
  highlighting queries under `$XDG_DATA_HOME/nvim/site` (default
  `~/.local/share/nvim/site`).

LaTeX parser generation exceeds small VMs' memory budget. The module uses
nixpkgs' prebuilt grammar and fetches queries from the pinned Tree-sitter plugin.
The smoke test checks that the parser revision matches the pinned registry and
that LaTeX parsing and highlighting work. When updating the Tree-sitter pin,
refresh the query-source hash and check grammar alignment. Existing LaTeX files may
need backing up on the first Home Manager activation; no files are force-replaced.

Mason retains LazyVim's installer for the configured language servers,
formatters and linters. Its binaries append to PATH so Nix commands take priority.
Project dependencies and SDKs still belong in the project's development shell;
optional Mason health warnings for unused ecosystems do not require installing
Ruby, PHP, or Rust globally. Alejandra comes from Nix rather than Mason's
Cargo-based installer.

Terraform requires allowing its unfree license in nixpkgs. Consumers supplying
tools externally can override `tools.nvim.runtimePackages` (use `lib.mkForce []`
to replace the defaults). Setting `tools.nvim.package = null` skips only the
editor binary; disabling the module skips both config and runtime packages.

Regression tests: `tests/check.sh nvim-config`. On Linux, build the actual module's
executables without activating Home Manager:

```sh
nix build --impure --file tests/nvim-runtime.nix runtime --out-link /tmp/nvim-runtime
PATH="/tmp/nvim-runtime/bin:$PATH" bash tests/nvim-smoke.sh cold
PATH="/tmp/nvim-runtime/bin:$PATH" bash tests/nvim-smoke.sh warm DIRECTORY
```

Use the cold run's printed directory for `DIRECTORY`. The tests isolate config,
data, state and cache, mirror the module's managed data files, bootstrap pinned
lazy.nvim and LazyVim revisions, verify active plugin pins and the unchanged lock,
and exercise parser loading, LaTeX highlighting, Mason installs, Biome, Bash LSP,
linting and Blink. Disabled plugins retained in the lock need not be installed.
The tests do not activate Home Manager or modify the live Neovim state.

## Regenerating

These tables are derived by evaluating each module on its own against a bare
home-manager configuration and subtracting an empty one, so they cannot
drift from the modules by editing prose. `docs/introspect.nix` holds that
evaluation; point its `hm` and `pkgs` flake references at the home-manager
and nixpkgs you want, then:

```
nix eval --impure --json -f docs/introspect.nix
```
